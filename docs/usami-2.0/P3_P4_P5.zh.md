# Usami 2.0：P3–P5 最小运行切片

更新日期：2026-10-21。本文记录 Customer Runtime、Episode Runner 与两阶段 Designer 的当前代码接口和边界。该实现用于离线工程验证，不代表真实模型已学会出题或能力已提升。

## 做到了什么

### P3：Customer 一侧的身份、委托与交易同意

`CustomerProfile` 在 Episode 开始前固定顾客身份、可委托的订单行、允许的准备操作、可披露事实、可接受的补款/到货/退货条件及授权有效期。Runtime 会验证顾客和订单行确实属于同一身份。新交易 Episode 使用 `CustomerProfileV2`：每个初始委托都必须引用公开请求中的原文片段，该片段必须能唯一对应冻结世界中的顾客订单行。交易任务还要求委托行集合与公开任务目标完全一致，不能靠私有配置额外授权未提出的对象。

Customer 的交易初始请求只有在 `CustomerProfileV2` 绑定了原文请求片段和唯一公开订单行时，才能建立准备委托；后续 `CustomerDecision` 可以建立或撤销委托、披露限定事实、接受或拒绝实际展示的报价。Service 工具调用不会创建 Customer 授权。成交同意绑定顾客、报价、报价条款哈希、所同意的操作和过期时间；结构化接受/拒绝字段还必须与顾客可见文本中的明确正向/负向表达一致。需要退货的退款还需单独的释放同意。

报价卡是独立事件，不作为 Service 自由文本计分。Customer 接受前以及离线 Replay 时，都会从当前 World 重新生成报价呈现并逐字段比较，避免“模型看见的报价”和实际成交条款不一致。Customer 同意后若同时请求结束，Runner 暂缓结束，让 Service 有机会消费该授权。

授权不会从任意自然语言自由推断：profile 仍是可信的权限上限；但新协议要求该上限逐项绑定顾客公开请求和冻结业务对象，不能只凭隐藏配置生成授权。此验证目前是确定性的有限文本匹配，不代表已经解决任意自然语言语义理解，也不构成真实 Customer LLM 保真度证据。历史 v1 Profile 和 Episode 保留原 Replay 兼容路径。

### P4：原生执行、评分与可离线重放

通过 `usami_v2.runtime.runner.run_episode()` 执行单个任务。每次 Service 写操作使用独立的 harness Engine；Reference / Sandbox 模式、Oracle、原生 trace Replay 均记录在工具证据中。Customer 身份和隐藏任务目标不放入 Service Prompt。只读任务和状态变更任务都由同一个 Runner 处理。

新 Episode 使用版本化 `OutcomeV2`，分别报告 `business_goal_success`、`process_errors`、`safety_violations` 和 `interaction_reliability`，同时保留兼容旧报告的 `final_goal_reached` 与合取式 `strict_task_success`。例如，Service 先尝试一次被 Engine 正确拦截的错误操作，随后完成退款，可记为业务目标完成、过程错误存在、安全违规不存在、交互可靠；严格成功仍为失败。Service 完成退款后若又错误地声称退款仍待处理，交易目标仍记为完成，错误沟通计入过程错误，严格成功为失败。成功的越权写操作会计入安全违规；仅被正确拦截的请求不会冒充已经发生的安全事故。服务协议错误也会单独记为过程错误与交互可靠性失败。顾客明确要求的必要信息仍是业务目标的一部分；额外错误事实不会抹掉已完成的交易目标。报价条款本身通过独立的报价/同意事件核验。

Replay 从冻结 World、预登记外部事件、Customer 事件和每次原生 Engine trace 重建状态；重算 Oracle、顾客授权、报价呈现、事实证据、对话消息、模型请求顺序和最终 Outcome。Episode 归档是私有数据：文件权限为 `0600`；如果目标的叶子目录由保存器新建，会设为 `0700`；写入不覆盖已有路径。模型请求和 Customer 私有资料可能包含敏感内容，调用方仍应指定受控本地目录。

Python API 示例：

```python
from pathlib import Path

from usami_v2.runtime.runner import EpisodeBudget, run_episode, save_episode

episode = run_episode(
    initial_world=world,
    task=task,
    profile=customer_profile,
    customer_agent=customer_adapter,
    service_agent=service_adapter,
    budget=EpisodeBudget(max_model_calls=20),
    mode="reference",
)
artifact = save_episode(episode, Path("/private/local-runs/episode.json"))
print(episode.outcome.model_dump(mode="json"))
print(artifact["replay"]["verified"])
```

Runner 导入时不查询凭据，也不发请求。只有显式构造 `OpenAICustomerAgent` / `OpenAIServiceAgent` 并调用 `run_episode()` 才会使用模型。确定性 Adapter 可声明 `uses_model = False`，因此 `max_model_calls=0` 仍能执行离线流程；未知 Adapter 默认按可能调用模型处理。在线 Adapter 必须为成功和失败请求都保留 `AgentCall`，否则 Runner 会按协议错误结束。

验证已归档 Episode：

```sh
python -m usami_v2.cli verify-episode --path /private/local-runs/episode.json
```

该命令离线运行 Engine / Oracle / Outcome Replay，不访问模型服务。World 与 Task 的构建和 Reference 业务可达性证明仍使用原有 `build`、`verify-build`、`certify-task` 和 `verify-task-certificate` 命令；业务状态可达不等于自然交互可达。

### P5：分阶段自主提案与质量诊断

`design_and_certify()` 分两阶段调用显式提供的 `DesignerProvider`：

1. Designer 提交受限 `ScenarioDraft`；编译器附加来源分布，Builder 依据预登记采样槽和种子创建冻结世界。非 SAT、Schema 错误或非法范围会形成带原因的尝试记录。
2. 只有第一阶段得到经独立校验的冻结世界后，Designer 才看到实体别名和实际状态并提交 `TaskDraft`。编译器将别名解析为该世界中真实存在的实体，附加分布/分区来源；Reference 对状态目标进行有界认证。

每阶段最多三次提交，反馈只包含编译/证明错误，不会把 Reference witness、隐藏答案或 Oracle 判定传给 Designer。任务参数错误会作为下一次任务提案的 validator feedback；场景已冻结后只修任务，不会悄悄重建世界。Task 可引用的历史证据必须同时来自 `train` 分区并属于显式白名单；held-out Task 不允许携带训练证据。

运行前质量向量记录 Business certificate、witness、业务后果类别、目标类型、可诊断证据和结构签名。结构签名忽略随机 ID 和种子，并保留任务目标、关系约束以及候选方案的相对业务后果。运行后向量单独记录错误、正确拒绝、合法操作、成本与可靠性。两个向量都是分析证据，不是 Customer/Designer Skill 的接受 Gate。

若需证明完整顾客交互，可显式传入可信 `interaction_certifier`，它必须返回绑定相同冻结 World 与 Task、且 Replay 通过的 Episode。没有该回调时，成功只表示业务 Reference 证书通过；质量状态会保留 `business_certified_interaction_pending`，不会冒充完整交互认证。没有私有 Customer 证明场景工厂时，Designer 会在任何模型请求发生前拒绝运行。

## 本轮一致性修正

- 新 Designer 交易目标为 `TaskSpecV2` / `GroundedRemedyGoal`：公开请求片段、对象描述和允许的每一种处置方式都必须在原始顾客请求中出现；目标行描述还须唯一匹配冻结世界中顾客拥有的行。无法由有限词法规则确认的目标会拒绝，而不是悄悄评分。
- 新顾客委托为 `CustomerProfileV2`：委托行必须由请求原文片段指向唯一的冻结订单行；交易目标和委托集合一一对应。报价同意字段必须与同回合顾客文本的明确肯定/否定表达一致。
- `OutcomeV2` 把业务目标、过程错误、安全违规和交互可靠性分开；旧 Task/Profile/Outcome 仍用于历史 Episode Replay，新建交易 Episode 则要求 V2 契约。
- 这些约束采用有限、可审计的英语/中文词法匹配和精确原文片段，不是通用语义判定器。它可能保守拒绝合法但未覆盖的自然表达；不得据此声称真实 Customer / Service 已被验证。
